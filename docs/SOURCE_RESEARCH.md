# Источники P0: исследование и реализация

Основание: `docs/TZ/TZ_AI_assistant_akimat.docx`, версия 1.0, 21.10.2026. Проверка источников: 01.11.2026.

## Строгие критерии

Раздел 8 содержит девять критериев: (1) три публичных источника и единая лента; (2) подразделение, тональность и уверенность; (3) фильтры/группировка; (4) кластеры и приоритет; (5) три дашборда с общими фильтрами, drill-down, XLSX/CSV/PDF; (6) тональность ≥80%, сфера ≥75% на тестовой выборке; (7) раздел 5 о праве/PII/человеке в контуре; (8) один официальный Direct либо демонстрационный поток с ограничением доступа и маскированием; (9) демонстрация на реальных данных.

Пункт 3.1.2 требует минимум три источника, но не предписывает именно Instagram + Telegram + VK и не требует три разных платформы. Direct учитывается отдельно от трёх публичных подключений. MVP обязательно включает дашборды 1–3 (3.8.7). Расписание ≤60 минут и ручной запуск — 3.1.4. Загрузка подготовленных записей допустима для демонстрации, но не закрывает пункт 9 о реальных данных.

## Выбор способов

| Площадка | Проверенный подход | Решение |
|---|---|---|
| Городской портал обращений | JSON API, открытый раздел | Публичный источник 1: разрешённый владельцем JSON endpoint; тексты обращений, не список жителей |
| Другой городской портал/форум | HTML с JSON-LD Comment/DiscussionForumPosting | Публичный источник 2: серверный HTML-парсинг структурированных обращений с датой; произвольную вёрстку адаптировать отдельно |
| Местное СМИ / обсуждения | RSS/Atom с комментариями жителей | Публичный источник 3: разрешённая лента обращений/комментариев; обычные редакционные новости не считать обращениями |
| Telegram, открытые каналы | Web preview технически доступен; API/Telethon требует отдельного контекста доступа | Не включать массовый scraping в Gemini pipeline: условия Telegram требуют индивидуального явного согласия всех соответствующих пользователей для AI-использования; согласия администратора канала недостаточно |
| Telegram Direct | Официальный Bot API getUpdates собственного бота | Реализован opt-in приём приватных текстов; токен даёт владелец; информированное согласие на каждое сообщение; без чтения чужой переписки |
| Instagram/Facebook | Официальный Instagram API для подключённых professional accounts, разрешения/App Review; Messaging API для Direct | Не использовать универсальный HTML scraping или Instaloader в этом MVP. Требуются приложение, разрешения и подключение владельцем; не выдавать API за поиск всех публичных профилей |
| VK | wall.get / wall.getComments через официальный API с допустимым токеном/разрешениями | Кандидат вместо одного публичного endpoint после проверки правил, назначения обработки и прав доступа. Нативный VK adapter сейчас не реализован |
| Reddit | API и отдельные условия доступа | Не требуется ТЗ, не выбран: нет подтверждённого городского покрытия/доступа |

Три URL настоящих источников и разрешения владельцев в репозитории отсутствуют. Вымышленные подключения не включены. Редактируются три существующих публичных слота; расширение количества/произвольный CRUD источников пока не реализовано.

## Первичные источники и GitHub

- [Закон РК «О персональных данных и их защите», Әділет](https://adilet.zan.kz/rus/docs/Z1300000094). Текст Әділет в исследовательском браузере требует JS; [официальное разъяснение gov.kz](https://www.gov.kz/org/aktobe-alga/press/article/details/229933?lang=ru) подтверждает необходимость основания обработки и хранения базы в РК. Публичная доступность не является универсальным разрешением обработки. Для трансграничной передачи отдельно проверять ст.16; переключатель приложения не заменяет правовое основание.
- [Telegram Content Licensing](https://telegram.org/tos/content-licensing): раздел AI запрещает scraping/aggregation для AI deployment; предусмотрено ограниченное исключение при индивидуальном информированном продолжающемся согласии. Поэтому произвольный публичный Telegram канал не включён.
- [Bot API getUpdates](https://core.telegram.org/bots/api#getupdates): polling, offset, allowed_updates; webhook и polling взаимоисключающие; обновления хранятся Telegram не дольше 24 часов.
- [Meta Instagram API](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api): коллекция Meta, ограничения consumer/professional accounts. [Meta о scraping](https://about.fb.com/news/2021/05/scraping-by-the-numbers/amp/): автоматический сбор ограничивается платформой.
- [python273/vk_api](https://github.com/python273/vk_api): Python wrapper официальных VK API; полезен как образец token/API-подхода, не требуется для Node.js fetch.
- [instaloader/instaloader](https://github.com/instaloader/instaloader): загрузка публикаций/метаданных Instagram; наличие библиотеки не даёт права обходить ограничения или собирать данные для этой задачи.
- [ergoncugler/web-scraping-telegram](https://github.com/ergoncugler/web-scraping-telegram): исследовательский сбор Telegram, пример отдельного Python/Telegram стека. Не включён из-за условий AI-использования и ненужной инфраструктуры.
- [Gemini models](https://ai.google.dev/gemini-api/docs/models): для запрошенного preview в `.env.example` указан `gemini-3-flash-preview`; доступность зависит от ключа/проекта, проверяется реальным вызовом.

Это инженерное исследование, а не заключение о законности конкретного набора. Юрисдикция сервера и разрешения реальных владельцев не проверены.

## Реализованный сквозной путь

React 19 + Next.js 16 Route Handler → server-only fetch → JSON/RSS/Atom/HTML JSON-LD → ключевые слова (любое совпадение) → маскирование → существующий Google GenAI SDK с JSON schema/Zod → дедупликация/кластеризация/приоритет → SQLite → обновлённый state → единая лента и дашборды. Gemini классифицирует, агрегаты вычисляются по сохранённым записям. Дополнительный AI SDK и Python сервис не нужны.

Администратор открывает «Источники» → «Настроить источник»: название, метод, HTTPS URL без токенов/query, ключевые слова, период 1–60 минут, документированное основание и разрешение. Сохранённые UI-настройки имеют приоритет над стартовыми env-подключениями. «Собрать» в LIVE реально запрашивает endpoint, затем Gemini. В DEMO загружает фиксированные RU/KZ сообщения того же source через общий pipeline; повторный сбор не создаёт дубликатов. Сообщения имеют явно демонстрационные ссылки example.org. В LIVE нет fallback на DEMO при ошибке.

HTML адаптер читает только JSON-LD Comment/DiscussionForumPosting; не запускает JS, не пытается обойти login/CAPTCHA и не извлекает случайный текст всей страницы. Отсутствие структурированных обращений с ISO датой — явная ошибка. JSON до 200 строк, пакет обработки до 30; это ограничение прототипа, не полноценная пагинация. Фоновое расписание запускается отдельным `npm run worker`; без worker автоматического сбора нет. Ручной сбор синхронный, не SSE: новая аналитика приходит по завершении пакета. Защита от двух одновременных запусков действует в пределах процесса; для нескольких процессов нужна SQL lease/очередь.

## Запуск LIVE

1. Заполнить `.env.local`: Gemini key/model, `AI_TRANSFER_APPROVED=true` после проверки основания и обезличивания, LIVE пароли и session secret. Секреты не вводятся в UI и не возвращаются API.
2. Запустить приложение; войти admin в LIVE; настроить три реальных разрешённых endpoint через панель.
3. Нажать «Собрать» у каждого; проверить счётчики/ленту, ссылки/даты/маскирование, графики и экспорт. Проверить повторный сбор и ошибки.
4. Запустить `npm run worker` на сервере в РК для часового расписания. SQLite локальный, WAL; сейчас workspace хранится JSON-документом в SQL таблице, не нормализованными таблицами Item/Source.

## Direct: официальный Telegram бот

Владелец создаёт официальный бот акимата и задаёт `CITYCOM_TELEGRAM_BOT_TOKEN`, `CITYCOM_TELEGRAM_OWNER_APPROVED=true`, `CITYCOM_DIRECT_KEY` (32 случайных байта в hex), Gemini конфигурацию. Не подключать одновременно webhook/другой polling consumer. Запрос `getUpdates` выполняется по кнопке Direct «Собрать» или worker. Изменение токена на другого бота требует сброса cursor администратором в БД/миграции; UI для этого пока нет.

В описании бота/перед отправкой владелец должен раскрыть оператора и цель, категории данных, Gemini и трансграничную передачу, срок 7 дней, способы отзыва согласия/удаления, ограничения сервиса (не экстренная служба). Согласие добровольное; отказ означает отсутствие AI-обработки. Точный префикс каждого отправляемого текста:

```
Согласен на обработку и передачу обезличенного текста в Gemini. Обращение: Нет отопления в доме.
```

Приватные сообщения без префикса, группы, channel_post, фото и другие типы пропускаются, исходный текст не сохраняется и не отправляется Gemini. Сам префикс не передаётся модели. Это технический opt-in, не замена полноценному информированию/проверке юридической силы согласия. Приложение не отправляет жителям ответы. Согласие на следующее сообщение требуется заново. Отзыв и удаление — через уполномоченного администратора, существующая функция удаления.

Сохраняются обезличенный текст, HMAC-производный идентификатор и аналитические поля; приватная ссылка пустая. Текст LIVE Direct зашифрован AES-256-GCM в SQLite, ключ хранится отдельно в env. Исходные сообщения Telegram не архивируются. Просмотр текста — существующий защищённый API только admin/analyst с журналом доступа. Общий state/экспорт содержит маскированное представление. Direct старше 7 дней по ingestedAt отфильтровывается при чтении и удаляется при следующей SQL записи/цикле worker. Удаление старых WAL/backup копий и шифрование диска требуют отдельной эксплуатации; AES в приложении не шифрует всю БД. DEMO Direct синтетический и не требует токена.

## Не закрытые доказательствами критерии

Нет предоставленных ключа Gemini, трёх разрешённых реальных endpoint и токена официального бота. Поэтому настоящий LIVE-вызов, три реальных подключения, задержка ≤5 секунд, качество на независимой выборке и демонстрация на реальных данных не подтверждены. Маскирование остаётся эвристическим и требует проверки на реальном наборе, особенно ФИО/адресов. Нельзя объявлять полное соответствие разделу 5 или готовность промышленного Direct по наличию этих функций.

## Результат проверки реализации

`npm run check` и production `npm run build` проходят. 21 серверный тест проходит с отдельной SQLite, в том числе HTML provenance, Telegram consent/private-only, DEMO для трёх источников и Direct с повторным сбором, шифрование текста LIVE в сырой SQL записи и TTL. У ПАВЛОДАРЭНЕРГО отображаются реальные обращения по теплоснабжению и электроснабжению с датами; ответы компании нужно отделять от обращений. Исходная страница содержит контактные данные — они не должны попадать в выгрузку/AI. Даты видны, но формат не ISO; необходим явный разбор и часовой пояс Asia/Qyzylorda.

У Открытого диалога подтверждено публичное чтение обращений, даты, номера и отдельные ссылки. Поток общереспубликанский; его нельзя выдавать за Павлодар без фильтра. Политика https://open.egov.kz/privacypolicycontroller/index описывает публичность сообщений и целевое использование персональных данных, но сама по себе не предоставляет универсального разрешения передачи персональных данных стороннему AI.

У Pavon страница https://pavon.kz/post/view/92200 не имеет собственных комментариев: присутствует боковая лента комментариев других публикаций. Её нельзя приписывать этой статье. Конкретные страницы с собственными комментариями: https://pavon.kz/post/view/92403 (ТЭЦ-2) и https://pavon.kz/post/view/93528 (безопасность светильников); подтверждены публичным просмотром. Время комментария не содержит полного ISO timestamp в текстовом представлении — адаптер должен извлекать надёжную полную дату из HTML, а не придумывать год.

Право на регулярный автоматизированный сбор и AI-обработку для этих трёх ресурсов не подтверждено условиями/разрешением владельцев. Не выставлять permission=true на основании одного HTTP 200. Эти ресурсы — конкретные кандидаты, а не уже работающие три LIVE-подключения. Текущий универсальный HTML JSON-LD adapter для них недостаточен; выбор метода JSON или RSS не изменяет формат сайта.

Проверенные ограничения альтернатив:

- Reddit: https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy требует явного предварительного одобрения API-доступа; публичный subreddit не означает свободный API. Нативного Reddit/OAuth адаптера в приложении нет.
- Telegram: https://telegram.org/tos/content-licensing требует соответствующего индивидуального согласия для AI-использования; произвольный публичный канал не подходит как безусловно разрешённый источник Gemini. Собственный opt-in бот остаётся отдельным Direct.
- Instagram: официальная коллекция Meta https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api описывает доступ к профессиональным аккаунтам и разрешения. Универсальный scraping произвольного профиля не подтверждён.
- VK: требуется проверка официальных условий и доступа wall.get/wall.getComments с допустимым токеном; в исследовательском браузере официальная документация метода не открылась. Не выдавать сторонние парсеры за доказательство разрешения.
- SeeClickFix: https://seeclickfix.com/open311/v2/docs и https://dev.seeclickfix.com/v2/recommendations/ документируют публичный API реальных городских проблем. Это зарубежные данные, другой JSON-контракт и география; без отдельного адаптера/условий использования не считать решением для Павлодара.
