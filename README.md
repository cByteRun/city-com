# CityCom — AI City Intelligence

Панель городской обратной связи Павлодара: публичное сообщение → анализ RU/KZ → городская проблема → объяснимый приоритет → подтверждение подразделения сотрудником → контроль статуса.

Next.js 16 / React 19 / TypeScript, shadcn-style компоненты на Radix, Tailwind 4, Recharts, серверный Google GenAI SDK, SQLite (Node 24), ExcelJS и PDFKit. Три обязательных дашборда и лента используют один сохранённый набор данных.

## Запуск

Требуется Node.js 24 и npm.

```bash
npm ci
npm run dev
```

Открыть `http://localhost:3000`. DEMO открывается автоматически и содержит только синтетические данные. Выбор роли в DEMO — средство проверки прав на демонстрационном наборе; он не предоставляет доступ к LIVE.

```bash
npm run typecheck
npm test
npm run build
npm start
```

Браузерные проверки запускаются при работающем приложении:

```bash
npx playwright install chromium
npm run test:browser
```

Для другого адреса: `CITYCOM_BASE_URL=http://localhost:3001 npm run test:browser`. Для установленного Chromium можно задать `CHROMIUM_PATH`. Тесты изменяют и сбрасывают **только DEMO**.

## LIVE

Скопировать `.env.example` в `.env.local`, заполнить серверные настройки, перезапустить приложение. Ключи нельзя передавать через `NEXT_PUBLIC_*`.

- `GEMINI_API_KEY`, `GEMINI_MODEL`: доступный в вашем аккаунте идентификатор модели. В LIVE нет подмены ответа локальными правилами.
- `AI_TRANSFER_APPROVED=true`: только после проверки допустимости передачи обезличенного публичного текста выбранному провайдеру.
- Пароли необходимых ролей `CITYCOM_*_PASSWORD`: минимум 12 символов; встроенных LIVE-паролей нет. Сотрудник подразделения ограничен сферой `CITYCOM_DEPARTMENT`.
- До трёх разрешённых JSON/RSS источников, их тип, URL, название и подтверждение `CITYCOM_SOURCE_n_APPROVED=true`.
- `CITYCOM_SESSION_SECRET`: устойчивый секрет сессий. Если не задан, для локального экземпляра он создаётся и хранится в SQLite.

JSON-коннектор ожидает массив:

```json
[{"text":"Публичное обращение","url":"https://source.example/post/1","publishedAt":"2026-10-31T10:00:00.000Z","authorId":"source-pseudonymous-id"}]
```

RSS должен содержать именно сообщения/публикации о городской обратной связи. Новостной заголовок нельзя автоматически выдавать за независимую жалобу жителя. Публикации без идентификатора автора не увеличивают счётчик независимых авторов. Репосты с одинаковым нормализованным текстом пропускаются.

В P0 одна операция принимает до 30 записей / файл до 2 МБ. Для более крупных источников требуется адаптер с курсором/пагинацией. Подключаемые адаптеры находятся в `src/server/connectors.ts`; ядро обработки не зависит от их формата.

Ручной сбор доступен на странице источников. Автоматический сбор:

```bash
npm run worker
```

Worker читает `.env.local`, проверяет расписания раз в минуту и запускает разрешённые источники с интервалом не более 60 минут. Он должен работать отдельным процессом. Ошибки сохраняются; отсутствие подключения отображается явно. Для Docker: создать `.env.local`, затем `docker compose up --build`. Web и collector используют общий том SQLite. Docker-конфигурация предоставлена, но в этой сессии не запускалась.

## Сценарий демонстрации

1. Открыть «Общую картину», выбрать период и сферу.
2. В «Проблемах и приоритетах» открыть проблему, сверить факторы и исходные сообщения.
3. Подтвердить подразделение и статус «Передано», затем «В работе» и «Решено».
4. В «AI-обработке» загрузить CSV/XLSX или ввести сообщение RU/KZ. Шаблон: `public/import-template.csv`.
5. Подтвердить или исправить неоднозначную классификацию в «Модерации».
6. Выгрузить текущую выборку в CSV/XLSX/PDF. В «Качестве» запустить smoke-проверку.
7. Проверить Direct demo и журнал доступа, затем сменить роль на просмотр / сотрудника подразделения.

Фильтры хранятся в URL; набор можно сохранить в браузере. Поддержаны светлая/тёмная темы, мобильная навигация, сортировка, группировка и постраничная лента. Локальный ассистент строит поисковую сводку по текущей выборке со ссылками на записи; это не генеративный RAG-чат.

## Границы подтверждённого результата

Работоспособность DEMO проверена через браузер и серверные тесты. LIVE-провайдер и три реальных источника в поставленной среде не настроены: сбор реальных данных, качество LIVE и реальная E2E-демонстрация пока **не подтверждены**. Эти критерии нельзя считать принятыми по одному виду интерфейса.

DEMO-классификатор — прозрачные локальные правила для демонстрации операций. 36 размеченных примеров RU/KZ — smoke-проверка, а не репрезентативный benchmark. Самооценка уверенности LLM не является калиброванной вероятностью. Исправления оператора сохраняются, но автоматического дообучения нет.

Direct P0 — только синтетический поток. Реальные Direct в LIVE отклоняются. Маскирование регулярными выражениями не гарантирует распознавание всех ФИО/адресов; перед промышленным подключением необходимы полноценная PII-проверка, шифрование, сроки хранения, управление персональными аккаунтами и инфраструктура в РК. SQLite и общие пароли ролей предназначены для локального MVP; целевые 10 000 записей/сутки, SLA 99%, промышленное HTTPS и масштабирование здесь не аттестованы.

### Языки интерфейса

Переключатель EN / RU / KZ в верхней панели меняет язык без сброса страницы,
фильтров и введённых данных. Выбор сохраняется в `localStorage` (`citycom.locale`)
и синхронизируется между вкладками. По умолчанию используется русский.
Для казахского применяется ISO-код `kk` и форматирование `kk-KZ`; `KZ` — подпись
переключателя. API экспорта принимает `locale=en|ru|kk` (также `kz`).

Словари находятся в `src/shared/i18n/{en,ru,kk}.json`. Переводятся подписи,
навигация, формы, графики, справочники, инструкция и заголовки отчётов.
Оригинальные сообщения, ответы AI, пользовательские названия источников и
редактируемое содержимое сохраняют исходный язык. Перевод интерфейса на EN
не расширяет предусмотренные ТЗ языки классификации обращений RU/KZ.

Проверки: `npm test` проверяет полноту словарей и параметры сообщений;
`npm run test:browser -- tests/browser/i18n.spec.ts` проверяет три языка,
экраны, сохранение выбора, фильтры и экспорт в браузере на работающем сервере.
